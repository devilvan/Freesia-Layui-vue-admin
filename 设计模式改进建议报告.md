# Freesia系统架构设计模式改进建议报告

## 一、现有架构分析

### 1.1 当前架构特点

系统采用标准的Spring Boot三层架构：
- **表现层（Controller）**：接收HTTP请求，进行VO到DTO的转换
- **业务层（Service）**：处理业务逻辑，协调Repository和Mapper
- **持久层（Repository/Mapper）**：数据访问，混合使用JPA和MyBatis-Plus

### 1.2 已使用的设计模式`

系统已经应用了以下设计模式：
1. **工厂模式**：`OssFactory` - OSS对象存储处理器工厂
2. **策略模式**：`ValidationStrategy` - 数据校验策略接口
3. **模板方法模式**：代码生成器使用FreeMarker模板
4. **适配器模式**：`RedisSaTokenHandler`适配SaTokenDao接口
5. **建造者模式**：`HttpBuilder`用于构建HTTP请求
6. **单例模式**：工具类采用私有构造函数

## 二、改进建议

### 2.1 Service层改进

#### 问题分析
- Service实现类中存在大量重复的CRUD操作代码
- 对象转换逻辑分散在各处
- 分页查询构建逻辑重复

#### 建议1：引入模板方法模式 + 泛型基础Service

**目标位置**：`freesia-common/freesia-common-framework`

创建通用的基础Service，提取公共的CRUD操作：

```java
public abstract class BaseServiceImpl<M extends BaseMapper<T>, T extends BasePo, D extends BaseDto> 
    extends ServiceImpl<M, T> {
    
    protected final UCopy copyUtil;
    
    /**
     * 保存或更新（模板方法）
     */
    public D saveUpdate(D dto) {
        T po = convertDto2Po(dto);
        // 钩子方法，子类可以重写以添加额外逻辑
        beforeSave(po, dto);
        T saved = getRepository().saveAndFlush(po);
        afterSave(saved, dto);
        return convertPo2Dto(saved);
    }
    
    /**
     * 分页查询（模板方法）
     */
    public TableResult<D> findPage(D dto, PageQuery pageQuery) {
        Wrapper<T> wrapper = buildQueryWrapper(dto);
        Page<T> page = page(pageQuery.build(), wrapper);
        return TableResult.build(convertPagePo2Dto(page, getDtoClass()));
    }
    
    // 抽象方法，由子类实现
    protected abstract JpaRepository<T, Long> getRepository();
    protected abstract Class<D> getDtoClass();
    protected abstract Wrapper<T> buildQueryWrapper(D dto);
    
    // 钩子方法，子类可选择重写
    protected void beforeSave(T po, D dto) {}
    protected void afterSave(T saved, D dto) {}
    
    protected T convertDto2Po(D dto) {
        return UCopy.copyDto2Po(dto, getPoClass());
    }
    
    protected D convertPo2Dto(T po) {
        return UCopy.copyPo2Dto(po, getDtoClass());
    }
}
```

**优势**：
- 减少Service实现类中重复代码
- 统一转换逻辑
- 提高代码可维护性

#### 建议2：引入转换器模式（Converter Pattern）

**目标位置**：`freesia-common/freesia-common-framework`

创建统一的转换器接口和实现，替代当前分散的UCopy调用：

```java
// 转换器接口（已存在：Converter.java）
public interface Converter<SOURCE, TARGET> {
    TARGET convert(SOURCE source);
    List<TARGET> convertBatch(List<SOURCE> sourceList);
}

// ClassPair类（已在ConverterFactory中定义，但需要确保正确实现equals和hashCode）
// 由于使用了Lombok的@Data注解，会自动生成equals和hashCode
// 但如果要作为Map的key使用，建议添加@EqualsAndHashCode注解确保正确性
// 文件位置：ConverterFactory.java 内部静态类
@Data
@EqualsAndHashCode  // 添加此注解确保equals和hashCode正确实现
@NoArgsConstructor
@AllArgsConstructor
public static class ClassPair {
    private Class<?> source;
    private Class<?> target;
}

// 反射转换器实现（需要新建：ReflectionConverter.java）
package com.freesia.convert;

import com.freesia.util.UCopy;
import lombok.AllArgsConstructor;

import java.util.ArrayList;
import java.util.List;

/**
 * @author Evad.Wu
 * @Description （转换器模式）反射转换器实现
 * @date 2026-01-04
 */
@AllArgsConstructor
public class ReflectionConverter<SOURCE, TARGET> implements Converter<SOURCE, TARGET> {
    private final Class<SOURCE> sourceClass;
    private final Class<TARGET> targetClass;
    
    @Override
    public TARGET convert(SOURCE source) {
        if (source == null) {
            return null;
        }
        try {
            TARGET target = targetClass.getConstructor().newInstance();
            UCopy.fullCopy(source, target);
            return target;
        } catch (Exception e) {
            throw new RuntimeException(
                String.format("对象转换失败: %s -> %s", sourceClass.getName(), targetClass.getName()), e);
        }
    }
    
    @Override
    public List<TARGET> convertBatch(List<SOURCE> sourceList) {
        if (sourceList == null || sourceList.isEmpty()) {
            return new ArrayList<>();
        }
        return UCopy.fullCopyList(sourceList, targetClass);
    }
}

// 转换器工厂（已存在：ConverterFactory.java，但ClassPair需要添加@EqualsAndHashCode）
@Component
public class ConverterFactory {
    private final Map<ClassPair, Converter> converters = new ConcurrentHashMap<>();
    
    @SuppressWarnings("unchecked")
    public <S, T> Converter<S, T> getConverter(Class<S> sourceClass, Class<T> targetClass) {
        ClassPair pair = new ClassPair(sourceClass, targetClass);
        return converters.computeIfAbsent(pair, 
            k -> new ReflectionConverter<>(sourceClass, targetClass));
    }
    
    // ClassPair内部类需要添加@EqualsAndHashCode
    @Data
    @EqualsAndHashCode  // 重要：确保作为Map key时正确工作
    @NoArgsConstructor
    @AllArgsConstructor
    public static class ClassPair {
        private Class<?> source;
        private Class<?> target;
    }
}

// 使用示例
@Service
public class SysUserServiceImpl extends BaseServiceImpl<...> {
    @Autowired
    private ConverterFactory converterFactory;
    
    public SysUserDto saveUpdate(SysUserDto dto) {
        Converter<SysUserDto, SysUserPo> dto2PoConverter = 
            converterFactory.getConverter(SysUserDto.class, SysUserPo.class);
        SysUserPo po = dto2PoConverter.convert(dto);
        // ...
    }
}
```

**实现步骤**：
1. **ConverterFactory.java**：在ClassPair类上添加`@EqualsAndHashCode`注解（Lombok会自动生成equals和hashCode方法）
2. **ReflectionConverter.java**：新建文件，实现Converter接口，基于UCopy工具类进行对象转换

**完整实现代码位置**：`freesia-common/freesia-common-framework/src/main/java/com/freesia/convert/`

**优势**：
- 统一对象转换逻辑
- 易于扩展自定义转换规则
- 便于后续集成MapStruct等工具

### 2.3 异常处理改进

#### 问题分析
- 异常处理分散在多个Aspect类中
- 异常类型和HTTP状态码映射不统一
- 缺少异常链处理机制

#### 建议5：引入责任链模式 + 异常处理器注册表

**目标位置**：`freesia-common/freesia-common-framework`

创建统一的异常处理链：

```java
// 异常处理器接口
public interface ExceptionHandler {
    boolean supports(Exception exception);
    R<?> handle(Exception exception, HttpServletRequest request);
    int getOrder(); // 优先级
}

// 异常处理器链
@Component
public class ExceptionHandlerChain {
    private final List<ExceptionHandler> handlers;
    
    public ExceptionHandlerChain(List<ExceptionHandler> handlers) {
        this.handlers = handlers.stream()
            .sorted(Comparator.comparing(ExceptionHandler::getOrder))
            .collect(Collectors.toList());
    }
    
    public R<?> handle(Exception exception, HttpServletRequest request) {
        return handlers.stream()
            .filter(h -> h.supports(exception))
            .findFirst()
            .map(h -> h.handle(exception, request))
            .orElse(R.failed("系统异常"));
    }
}

// 统一异常处理切面
@RestControllerAdvice
public class GlobalExceptionAspect {
    private final ExceptionHandlerChain handlerChain;
    
    @ExceptionHandler(Exception.class)
    public R<?> handleException(Exception e, HttpServletRequest request) {
        return handlerChain.handle(e, request);
    }
}
```

**优势**：
- 统一异常处理逻辑
- 易于扩展新的异常类型
- 支持异常处理的优先级控制

```java
// 查询条件构建器
public class QueryWrapperBuilder<T extends BasePo> {
    private final LambdaQueryWrapper<T> wrapper;
    
    public static <T extends BasePo> QueryWrapperBuilder<T> create(Class<T> poClass) {
        return new QueryWrapperBuilder<>(Wrappers.lambdaQuery(poClass));
    }
    
    public QueryWrapperBuilder<T> eqIfNotNull(String column, Object value) {
        if (value != null) {
            wrapper.eq(getColumn(column), value);
        }
        return this;
    }
    
    public QueryWrapperBuilder<T> likeIfNotEmpty(String column, String value) {
        if (StringUtils.isNotEmpty(value)) {
            wrapper.like(getColumn(column), value);
        }
        return this;
    }
    
    public QueryWrapperBuilder<T> dateRange(String column, Date from, Date to) {
        if (from != null && to != null) {
            wrapper.between(getColumn(column), from, to);
        }
        return this;
    }
    
    public LambdaQueryWrapper<T> build() {
        return wrapper;
    }
}

// 使用示例

    .likeIfNotEmpty("userName", dto.getUserName())
    .dateRange("createTime", dto.getCreateTimeFrom(), dto.getCreateTimeTo())
    .build();
```

#### 建议8：引入策略模式 + 规则引擎

**目标位置**：`freesia-common/freesia-common-validation`

创建业务规则引擎：

```java
// 业务规则接口
public interface BusinessRule<T> {
    boolean evaluate(T context);
    String getErrorMessage();
    int getPriority();
}

// 规则引擎
@Component
public class BusinessRuleEngine {
    private final Map<Class<?>, List<BusinessRule>> rules;
    
    public <T> ValidationResult validate(T context) {
        List<BusinessRule<T>> applicableRules = getRulesFor(context.getClass());
        
        for (BusinessRule<T> rule : applicableRules) {
            if (!rule.evaluate(context)) {
                return ValidationResult.failed(rule.getErrorMessage());
            }
        }
        
        return ValidationResult.success();
    }
}

// 用户业务规则示例
@Component
public class UserNameUniqueRule implements BusinessRule<SysUserDto> {
    private final SysUserService userService;
    
    @Override
    public boolean evaluate(SysUserDto user) {
        return userService.checkUserNameUnique(user);
    }
    
    @Override
    public String getErrorMessage() {
        return "用户名已存在";
    }
}
```

**优势**：
- 业务规则与业务逻辑解耦
- 易于扩展和修改规则
- 支持规则的优先级控制

### 2.7 服务编排改进

#### 问题分析
- 复杂业务流程中Service之间的调用关系复杂
- 缺少统一的事务管理
- 业务流程难以追踪

#### 建议9：引入命令模式 + 工作流引擎

**目标位置**：`freesia-common/freesia-common-workflow`

创建简单的工作流引擎：

```java
// 命令接口
public interface Command {
    void execute();
    void undo();
}

// 工作流步骤
public class WorkflowStep {
    private final String name;
    private final Command command;
    private final List<WorkflowStep> nextSteps;
    
    public WorkflowStep execute() {
        try {
            command.execute();
            return this;
        } catch (Exception e) {
            command.undo();
            throw new WorkflowException("步骤执行失败: " + name, e);
        }
    }
}

// 工作流引擎
@Component
public class WorkflowEngine {
    public void execute(Workflow workflow) {
        WorkflowStep currentStep = workflow.getStartStep();
        
        while (currentStep != null) {
            currentStep = currentStep.execute().getNextStep();
        }
    }
}

// 使用示例：用户注册工作流
Workflow registerWorkflow = Workflow.builder()
    .step("validate", new ValidateUserCommand(userDto))
    .step("saveUser", new SaveUserCommand(userDto))
    .step("sendEmail", new SendWelcomeEmailCommand(userDto))
    .build();
    
workflowEngine.execute(registerWorkflow);
```

**优势**：
- 业务流程清晰可见
- 支持事务回滚
- 易于扩展和修改流程

## 三、设计模式组合建议

### 3.1 模板方法 + 策略模式组合

**应用场景**：Service层的CRUD操作

```java
public abstract class BaseServiceImpl<D extends BaseDto> {
    // 模板方法
    public D saveUpdate(D dto) {
        validate(dto); // 策略：使用规则引擎
        T po = convert(dto); // 策略：使用转换器
        beforeSave(po, dto); // 钩子方法
```

**应用场景**：OSS存储、缓存策略选择

**应用场景**：查询条件构建、HTTP请求构建

## 四、实施优先级建议

### 高优先级（立即实施）
1. **Service层模板方法模式** - 减少重复代码，影响范围大
2. **转换器模式** - 统一对象转换，提高代码质量
3. **查询构建器** - 减少查询代码重复

### 中优先级（近期实施）
4. **异常处理责任链** - 统一异常处理逻辑
5. **缓存管理器** - 统一缓存操作
6. **业务规则引擎** - 解耦业务规则

### 低优先级（长期优化）
7. **工作流引擎** - 复杂业务流程管理
8. **OSS存储重构** - 存储策略优化
9. **Controller层AOP优化** - 简化Controller代码

## 五、实施注意事项

1. **渐进式重构**：不要一次性重构所有代码，按模块逐步实施
2. **保持向后兼容**：新设计要与现有代码兼容，避免影响现有功能
3. **充分测试**：每个重构步骤都要有对应的测试用例
4. **文档更新**：及时更新架构文档和开发规范
5. **团队培训**：确保团队成员理解新的设计模式和使用方式

## 六、总结

通过引入和组合使用设计模式，可以显著提升系统的：
- **可维护性**：代码结构清晰，易于理解和修改
- **可扩展性**：新功能易于添加，符合开闭原则
- **可测试性**：组件解耦，便于单元测试
- **代码质量**：减少重复代码，提高代码复用率

建议按照优先级逐步实施，确保系统稳定性的同时逐步提升代码质量。
